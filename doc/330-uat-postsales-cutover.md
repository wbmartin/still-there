# UAT cutover — presales bundle → post-sales pipeline

The runbook that moves the UAT host from the presales bundle
(`bin/600-bundle-uat` / `bin/610-deploy-uat`,
`doc/320-presales-uat-deploy.md`) onto the webhook → tests → registry →
migrator pipeline in `infra/uat/` (`infra/README.md`). The host is
reloaded from your **local** database, as a credential-scrubbed export
(0.4), and `doc/331-prd-postsales-install.md` loads prod from the same
export the same day, so prod runs nothing UAT has not (Brandon,
2026-10-02: "we setup UAT and Prod with whatever we've been working on
our locals").

It is a migration, not a switch: the role model, env files, units and
the restart mechanism all differ, and the database changes owner. UAT
takes an outage from A1 to A8: one straight sequence beats staging a live
swap. The presales database is **renamed aside**, not dropped or re-owned:
it is the rollback, and the rollback is one statement.

This shape ran on real hosts in a derived app on 2026-10-01; this generic
form has not run as written yet. Tick each step off as it runs and add
what surprised you to **Lessons** at the bottom.

## Which path am I on?

| Signal on the host | Presales | Post-sales |
|---|---|---|
| API binary | `libexec/api-srv` | `libexec/api-srv` (+ `proto-api.revision`) |
| API env file | `etc/api-srv.env` | `etc/uat-proto-api.env` |
| Migrator env | none — `610` passes the API env to `proto-migrate` | `etc/uat-proto-migrate.env` (DDL role) |
| systemd unit | `etc/uat-proto-api.service`, generated by `610` on first run, `User=www-data` | `etc/uat-proto-api.service` shipped from `infra/`, `User=proto`, plus `uat-proto-restart.{path,service}` |
| Postgres owner of every table | `proto_app` (also the API's login) | `proto_ddl` (migrator only); the API logs in as `proto_app`, DML only |
| How a deploy arrives | tarball in `/tmp`, `sudo ./deploy.sh` | push → GitHub webhook → `shrmpl-hook` → `bin/uat-proto-build` |
| How the DB changes | wholesale restore of the laptop dump | `proto-migrate verify → pending → pg_dump → up` |
| TLS certs | as `doc/320` host prep set them up (usually certbot's own) | copies in `crt/<site>/` from `uat-proto-renew-web-certs` (root cron) |
| Monitoring, fail2ban | none | nackmon (cert renewal), pulsecheck (api, web), the `[uat-proto]` jail |
| `/srv/uat-proto/bin/` | absent | the `infra/uat/bin/` scripts |

## 0. Before the outage

Nothing below touches the running app. **Local blocks** run in your
terminal from the repo root, usually zsh: they carry no inline `#`
comments, because zsh without `setopt interactivecomments` (the macOS
default) runs `#` as a command and an apostrophe in a "comment" opens a
quote that swallows the lines after it. They read the hosts' ssh aliases
from `UAT_SSH` and `MON_SSH` (the host that runs nackmon and pulsecheck;
it may be UAT itself), and `EXPORT_DIR`, a directory outside the repo and
off shared drives where 0.4 writes the data: set all three once in that
terminal. **Host blocks** run in bash as root (`sudo -i`).

**0.1 Have to hand**

- GitHub admin on the repository (A3 adds a deploy key, B1 a webhook).
- The registry server, user and password, the Slack webhook URL and the
  certbot e-mail. If other apps on the host deploy this way, their deploy
  env files hold them: `sudo grep -h -e CONTAINER_REGISTRY -e SLACK_WEBHOOK
  -e CERTBOT_EMAIL /srv/*/etc/*deploy.env`.
- The tools, on UAT (prints nothing when all are there):

```bash
for t in git go npm oras jq psql pg_dump pg_restore certbot nginx fail2ban-client openssl; do command -v "$t" >/dev/null || echo "missing: $t"; done
id shrmpl-hook >/dev/null || echo "missing: the shrmpl-hook user"
```

- A record of the host as it is now, before anything below changes it:
  users, tools, `/srv`, units, Postgres roles, databases and owners,
  nginx, fail2ban, cron, ports. `bin/605-survey-host` is read-only; it
  asks for your sudo password once and saves `tmp/survey/<host>-<stamp>.txt`.
  Env files appear as key names only and the rest passes a best-effort
  secret mask: read the file before you share it. Keep it until C; it is
  what a rollback or a later question is checked against. Locally:

```bash
: "${UAT_SSH:?}"
bin/605-survey-host "$UAT_SSH"
```

**0.2 Local: the ids.** The nackmon check-in code and the webhook id are
part of each file's name on the host, and the repo mirrors the host, so
the files are renamed and committed first; the checkout A3 makes then
carries them. Ids come from `/proc/sys/kernel/random/uuid`, which every
Linux kernel has (`uuidgen` is not installed everywhere). Commit to the
branch UAT builds (`BRANCH_TO_CHECKOUT`, `main` in the template), through
your usual review if it is protected:

```bash
: "${UAT_SSH:?}"
N=infra/uat/shrmpl-etc/nack-monitors
H=infra/uat/shrmpl-etc/hooks
git mv "$N/uat-proto-renew-web-certs_NACKID.env" "$N/uat-proto-renew-web-certs_$(ssh "$UAT_SSH" cat /proc/sys/kernel/random/uuid).env"
git mv "$H/build-proto_HOOKID.env" "$H/build-proto_$(ssh "$UAT_SSH" cat /proc/sys/kernel/random/uuid).env"
ls $N $H
git commit -m "uat-proto: nackmon check-in id and build hook id"
git push
```

**0.3 The cert-renewal monitor, on the monitoring host.** A8's renewal
script checks in with nackmon as its last step, so the monitor exists
before A8. Locally:

```bash
: "${MON_SSH:?}"
scp infra/uat/shrmpl-etc/nack-monitors/uat-proto-renew-web-certs_*.env "$MON_SSH:/tmp/"
```

On the monitoring host, as root. `REF` is an existing monitor whose owner

```bash

```

Expect `0`, then `active`.

**0.4 Local: the data.** The local database is what UAT, and later prod,
start from. `bin/620-export-tenant-data` copies it into a throwaway
database, scrubs every credential there
(`src/api-srv/sql/export-scrub.sql`) and dumps that copy into
`EXPORT_DIR`; the local database is only read. Before you run it:

- Remove what must not ship. The scrub refuses, naming what it found, any
  row in tenant 2 (the test tenant) and the seeded fixture logins
  (`admin`, `basic`, `mfa`, `switcher`: their passwords are in the repo).
  Rename or delete those in the app first.
- No login keeps a credential: every password, MFA enrolment and MFA
  exemption is cleared, every live login becomes `invited` (a blocked one
  stays blocked) and open invite links are revoked. Nobody signs in on a
  host with anything that lived on this laptop; the first person in
  comes through a link A9 issues there, and invites the rest.
- From the export on, **nobody edits the local data** until prod has
  loaded the same file (`doc/331`). Anything entered locally later is on
  neither host; if that happens, export again and load that.
- The export is the customer's data: it never goes in the repo (the
  script refuses an `EXPORT_DIR` inside the checkout) or on a shared
  drive. Delete it once prod has loaded it.

`git status --short` empty and the branch pushed first. The script stops
unless the database's `schema_migration` matches this checkout's
migrations exactly (none pending, none edited), and the manifest records
the commit, the schema version, rows per table per tenant and every
login with its status. The host's Postgres must be the same major version
as the manifest's `pg_dump=` line or newer.

```bash
: "${UAT_SSH:?}" "${EXPORT_DIR:?}"
bin/620-export-tenant-data "$EXPORT_DIR"
source etc/app.env
DUMP=$(ls -t "$EXPORT_DIR"/$APP_SLUG-data-*.dump | head -1)
echo "$DUMP"
scp "$DUMP" "$DUMP.sha256" "$UAT_SSH:/tmp/"
```

## A. Cutover — UAT is down from A1 to A8

One pass, in order, in **one root shell** on UAT (`sudo -i`). If the shell
is lost, paste this block again and carry on: every later value is read
back from a file, and the env-file step only fills what still says
`SERVERONLY`.

```bash
ENV=uat; APP_ROOT=/srv/uat-proto; OLD=/root/uat-proto-presales
REPO=/build-stg/proto; I=$REPO/infra/uat; SQL=$REPO/infra/sql/proto-host-db.sql
getv()  { sed -n "s/^$2=//p" "$1" 2>/dev/null | head -1; }
urlpw() { sed -n 's#^DATABASE_URL=postgres://[^:]*:\([^@]*\)@.*#\1#p' "$1" | head -1; }
urldb() { sed -nE 's#^DATABASE_URL=postgres://[^/]+/([^?]+).*#\1#p' "$1" | head -1; }
idof()  { f=$(ls "$I/shrmpl-etc/$1/$2"_*.env 2>/dev/null | head -1); f=${f##*/"$2"_}; echo "${f%.env}"; }
fill()  { [ -n "$3" ] || { echo "[skip] $2: no value, fill it by hand"; return; }
  ( umask 077; K="$2" V="$3" awk 'index($0, ENVIRON["K"] "=") == 1 && /SERVERONLY/ { print ENVIRON["K"] "=" ENVIRON["V"]; next } { print }' "$1" > "$1.new" ) && cat "$1.new" > "$1" && rm "$1.new"; }
fillpw() { ( umask 077; R="$2" V="$3" awk '{ s = ENVIRON["R"] ":SERVERONLY@"; i = index($0, s) } i { $0 = substr($0, 1, i - 1) ENVIRON["R"] ":" ENVIRON["V"] "@" substr($0, i + length(s)) } { print }' "$1" > "$1.new" ) && cat "$1.new" > "$1" && rm "$1.new"; }
```

`fill FILE KEY VALUE` sets `KEY=VALUE` only on a line that still holds
`SERVERONLY`; `fillpw FILE ROLE PASSWORD` replaces `ROLE:SERVERONLY@` in a
`DATABASE_URL`. Both take the value through the environment, never a
command line, so a re-run never regenerates a secret already in use and no
secret shows in `ps`.

### A1. Stop presales and keep a copy of it

The presales `etc/`, `libexec/` and `web-pub/` go to `$OLD`; the database
is renamed `<name>_presales`. The presales nginx site stays until A8:
nginx keeps serving `web-pub/`, and certbot has a server block to answer
its challenge from. `/api/` answers 502 until A7.

```bash
: "${APP_ROOT:?}" "${OLD:?}"
systemctl stop uat-proto-api
mkdir -p "$OLD"
[ -d "$OLD/etc" ] || cp -a "$APP_ROOT/etc" "$OLD/etc"
[ -d "$OLD/web-pub" ] || cp -a "$APP_ROOT/web-pub" "$OLD/web-pub"
[ -d "$OLD/libexec" ] || mv "$APP_ROOT/libexec" "$OLD/libexec"
rm -f "$APP_ROOT/etc/api-srv.env" "$APP_ROOT/etc/deploy.env"
rm -rf "$APP_ROOT/web-pub.prev"
OLD_DB=$(urldb "$OLD/etc/api-srv.env"); echo "OLD_DB=$OLD_DB"
sudo -u postgres psql -X -v ON_ERROR_STOP=1 -c "ALTER DATABASE \"$OLD_DB\" RENAME TO \"${OLD_DB}_presales\""
```

### A3. The checkout the hook builds from

Owned by `shrmpl-hook`: never run git or go in it as root, or the next
hook build trips on root-owned files. GitHub deploy keys are per
repository, so this repository gets its own key and ssh alias,
`github-proto`:

```bash
install -d -m 700 -o shrmpl-hook -g shrmpl-hook ~shrmpl-hook/.ssh
[ -e ~shrmpl-hook/.ssh/proto-deploy ] || sudo -u shrmpl-hook -H ssh-keygen -t ed25519 -N '' -C "$(hostname) proto deploy" -f ~shrmpl-hook/.ssh/proto-deploy
grep -qx 'Host github-proto' ~shrmpl-hook/.ssh/config 2>/dev/null || sudo -u shrmpl-hook -H tee -a ~shrmpl-hook/.ssh/config >/dev/null <<'CFG'
Host github-proto
  HostName github.com
  User git
  IdentityFile ~/.ssh/proto-deploy
  IdentitiesOnly yes
CFG
cat ~shrmpl-hook/.ssh/proto-deploy.pub
```

**Stop here:** GitHub → the repository → Settings → Deploy keys → Add,
paste the key, read-only. Then set `REPO_URL` in this shell to the
repository's ssh clone URL with `github.com` replaced by the alias
(`git@github-proto:` then owner/name `.git`), and clone (answer `yes` if
asked to trust github.com's host key):

```bash
: "${REPO:?}" "${REPO_URL:?}"
mkdir -p "$REPO" && chown shrmpl-hook:shrmpl-hook "$REPO"
sudo -u shrmpl-hook -H git clone "$REPO_URL" "$REPO"
sudo -u shrmpl-hook -H git -C "$REPO" log --oneline -1
ls "$I/shrmpl-etc/nack-monitors" "$I/shrmpl-etc/hooks"
```

Expect 0.2's commit, and both files named with an id, not `NACKID` /
`HOOKID`.

### A4. Directories, scripts, env files

The app root becomes `root:shrmpl-hook 1775`: the hook creates and renames
its own entries (the `web-pub/` swap, `stg/`, `backup/`), and the sticky
bit keeps it off what it does not own (`etc/`, `crt/`, `log/`). Units are
always copied (the shipped unit replaces the one `610` generated); an env
file only when the host has none yet.

```bash
: "${APP_ROOT:?}" "${I:?}"
mkdir -p "$APP_ROOT"/{bin,etc,libexec,stg,backup,crt,log,web-pub}
chown root:shrmpl-hook "$APP_ROOT" && chmod 1775 "$APP_ROOT"
chown -R shrmpl-hook:shrmpl-hook "$APP_ROOT"/{bin,libexec,stg,backup,web-pub}
chown -R www-data:www-data "$APP_ROOT/log"
cp "$I"/bin/* "$APP_ROOT/bin/" && chmod 0755 "$APP_ROOT"/bin/* && chown shrmpl-hook:shrmpl-hook "$APP_ROOT"/bin/*
cp "$I/etc/uat-proto-api.service" "$I/etc/uat-proto-restart.path" "$I/etc/uat-proto-restart.service" "$APP_ROOT/etc/"
for f in "$I"/etc/uat-proto-*.env; do [ -e "$APP_ROOT/etc/${f##*/}" ] || cp "$f" "$APP_ROOT/etc/"; done
chown root:proto "$APP_ROOT/etc/uat-proto-api.env" && chmod 0640 "$APP_ROOT/etc/uat-proto-api.env"
for f in deploy migrate test e2e-api; do chown root:shrmpl-hook "$APP_ROOT/etc/uat-proto-$f.env" && chmod 0640 "$APP_ROOT/etc/uat-proto-$f.env"; done
stat -c '%U:%G %a' "$APP_ROOT"
```

Expect `root:shrmpl-hook 1775`. Then the generated secrets, straight into
the files (A5 reads the passwords back from them). The CI password is in
two files and must match:

```bash
: "${APP_ROOT:?}" "${REPO:?}"
E=$APP_ROOT/etc
fillpw "$E/uat-proto-api.env" proto_app "$(openssl rand -hex 32)"
fillpw "$E/uat-proto-migrate.env" proto_ddl "$(openssl rand -hex 32)"
fill "$E/uat-proto-api.env" JWT_SECRET "$(openssl rand -hex 32)"
fill "$E/uat-proto-api.env" TOTP_ENCRYPTION_KEY "$(openssl rand -hex 32)"
fill "$E/uat-proto-test.env" 'export PGPASSWORD' "$(openssl rand -hex 32)"
fillpw "$E/uat-proto-e2e-api.env" proto_ci "$(getv "$E/uat-proto-test.env" 'export PGPASSWORD')"
fill "$E/uat-proto-deploy.env" REPO_URL "$(sudo -u shrmpl-hook -H git -C "$REPO" remote get-url origin)"
echo "nackmon id: $(idof nack-monitors uat-proto-renew-web-certs)"
grep -n '^[^#].*SERVERONLY' "$E"/uat-proto-*.env
```

The grep lists what is left, all in `uat-proto-deploy.env`: the three
`CONTAINER_REGISTRY_*`, `SLACK_WEBHOOK` (the whole URL), `CERTBOT_EMAIL`
(0.1), and `CERT_HEALTHCHECK_URL`: nackmon's check-in URL ending `?code=`
and the id printed above. Edit them in:

```bash
vi /srv/uat-proto/etc/uat-proto-deploy.env
```

```bash
: "${APP_ROOT:?}"
grep -n '^[^#].*SERVERONLY' "$APP_ROOT"/etc/uat-proto-*.env || echo "all filled"
```

`all filled` is the only acceptable answer. The JWT and TOTP keys are new
on purpose: every local session dies (MFA enrolments did not ship: 0.4).

### A5. Roles, the database, the data

(`doc/340-db-host-setup.md`). The roles and the new database, with the
passwords from the env files on psql's stdin (never `psql -v`, which is
argv):

```bash
: "${ENV:?}" "${APP_ROOT:?}" "${SQL:?}"
{ printf '\\set db %s\n'     "$(urldb "$APP_ROOT/etc/$ENV-proto-migrate.env")"
  printf '\\set ddl_pw %s\n' "$(urlpw "$APP_ROOT/etc/$ENV-proto-migrate.env")"
  printf '\\set app_pw %s\n' "$(urlpw "$APP_ROOT/etc/$ENV-proto-api.env")"
  printf '\\set ci_pw %s\n'  "$(getv "$APP_ROOT/etc/$ENV-proto-test.env" 'export PGPASSWORD')"
  cat "$SQL"
} | sudo -u postgres psql -X
```

Expect a last row `uat_proto_db | proto_ddl |
{=T/proto_ddl,proto_ddl=CTc/proto_ddl,proto_app=c/proto_ddl}`. An `ERROR`
stops it before anything changes; A1's rename not done is the likely one.
`proto_app` keeps its name and takes its new password. Then the dump 0.4
shipped, checked:

```bash
DUMP=$(ls -t /tmp/proto-data-*.dump | head -1); echo "DUMP=$DUMP"
(cd /tmp && sha256sum -c "${DUMP##*/}.sha256")
```

Expect `OK`. Restore it as `proto_ddl`, check that no credential came
with it, and check the owner:

```bash
: "${APP_ROOT:?}" "${DUMP:?}"
DB=$(urldb "$APP_ROOT/etc/uat-proto-migrate.env")
sudo -u postgres pg_restore --no-owner --no-privileges --role=proto_ddl --exit-on-error -d "$DB" < "$DUMP"
sudo -u postgres psql -X -d "$DB" -Atc "SELECT count(*) FROM app_user WHERE pw_hash <> '' OR totp_seed <> '' OR (account_status = 'active' AND delete_ts IS NULL)"
sudo -u postgres psql -X -d "$DB" -c "SELECT tableowner, count(*) FROM pg_tables WHERE schemaname = 'public' GROUP BY 1"
```

Expect `0` (0.4's scrub), then one row, `proto_ddl | <n>`. Then the negative checks: the API's
role reads but cannot create, the CI role cannot connect:

```bash

PGPASSWORD=$(urlpw "$APP_ROOT/etc/uat-proto-api.env") psql -X -h 127.0.0.1 -U proto_app -d "$DB" -c 'SELECT count(*) FROM app_user' -c 'CREATE TABLE nope (i int)'

```

Expect the user count, `ERROR:  permission denied for schema public`, and
`FATAL:  permission denied for database`.

### A7. First build, by hand

— the script the webhook will run:

```bash
sudo -u shrmpl-hook -H /srv/uat-proto/bin/uat-proto-build
```

Expect, in order: Slack *started* (full sha), the toolchain check
(`GOTOOLCHAIN=auto` fetches the Go that `src/api-srv/go.mod` names), the
Go and web builds, `oras push` of `proto-api` and `proto-web`, then
`uat-proto-install-api`: `verify: database matches the embedded
migrations` and `migrate: nothing pending` (or, if the build carries a
migration newer than the dump, a `backup/pre-migrate-*.dump` and then
`up`), the restart, `uat-proto-api healthy` and the revision; the web
publish; Slack *deployed*. Then the test suite runs against the deployed
commit: green tags `sha-<commit>-passed` and Slacks *tests passed*; red
Slacks *tests FAILED* with the failing step and tests, leaves the deploy
in place and the commit unpromotable (`prd-proto-promote-uat` refuses a
build without that tag). A deploy failure Slacks *FAILED at <step>* with
the commit; a second run waits for the first (up to 30 min). The first
run downloads Go modules and npm packages: allow several minutes.

### A8. Certificates, then the new nginx site

The renewal script runs first, against the presales site still in place,
and leaves its copies in `crt/<site>/` (`fullchain.pem` root:www-data
0640, `privkey.pem` root:root 0600); the new site reads them, so it is
linked only after. The presales site is moved to `$OLD`; if `nginx -t`
fails, it goes straight back and the new link comes out:

```bash
: "${APP_ROOT:?}" "${I:?}" "${OLD:?}"
SITE=$(getv "$APP_ROOT/etc/uat-proto-deploy.env" SITE_NAME); echo "SITE=$SITE"
"$APP_ROOT/bin/uat-proto-renew-web-certs"
ls -l "$APP_ROOT/crt/$SITE"
SRC=$(ls "$I"/etc/nginx_* | head -1); REPO_SITE=${SRC##*/nginx_}
sed "s/${REPO_SITE//./\\.}/$SITE/g" "$SRC" > "$APP_ROOT/etc/nginx_$SITE"
OLD_SITE=$(for f in /etc/nginx/sites-enabled/*; do [ "$(readlink -f "$f")" = "$APP_ROOT/etc/nginx_$SITE" ] || grep -l "server_name.*$SITE" "$f"; done | head -1); echo "presales site: ${OLD_SITE:-none}"
[ -z "$OLD_SITE" ] || { echo "$OLD_SITE" > "$OLD/nginx-site.path"; mv "$OLD_SITE" "$OLD/nginx-site"; }
ln -sf "$APP_ROOT/etc/nginx_$SITE" "/etc/nginx/sites-enabled/$SITE"
if nginx -t; then systemctl reload nginx && echo "reloaded"; else rm "/etc/nginx/sites-enabled/$SITE"; [ -z "$OLD_SITE" ] || mv "$OLD/nginx-site" "$OLD_SITE"; echo "nginx -t FAILED: presales site restored"; fi
curl -fsS "https://$SITE/api/health"
```

Expect the renewal script's `renewed; nginx reloaded; nackmon checked in`,
the two pem files, `reloaded`, and the health JSON.

### A9. First login

Every login arrived `invited`, with no password (0.4), so the first one in
comes through an invite link issued here. Pick a login that administers
its tenant (the manifest's `logins.tenant_<n>` line lists them); a second
tenant needs its own. The token is printed once and never stored: only its
SHA-256 goes into `user_invite`, exactly as the API stores the links it
issues, and the link lives `INVITE_TTL_HOURS`:

```bash
: "${ENV:?}" "${APP_ROOT:?}"
LOGIN=the-admin-login-to-invite
DB=$(urldb "$APP_ROOT/etc/$ENV-proto-migrate.env")
TTL=$(getv "$APP_ROOT/etc/$ENV-proto-api.env" INVITE_TTL_HOURS)
SITE=$(getv "$APP_ROOT/etc/$ENV-proto-deploy.env" SITE_NAME)
TOKEN=$(openssl rand -hex 32)
HASH=$(printf %s "$TOKEN" | sha256sum | cut -d' ' -f1)
sudo -u postgres psql -X -v ON_ERROR_STOP=1 -d "$DB" -v login="$LOGIN" -v hash="$HASH" -v ttl="$TTL" <<'SQL'
INSERT INTO user_invite (security_context_id, app_user_id, token_hash,
       expires_ts, create_ts, create_user_id, update_ts, update_user_id)
SELECT security_context_id, app_user_id, :'hash',
       extract(epoch FROM now()) + :ttl * 3600,
       extract(epoch FROM now()), 0, extract(epoch FROM now()), 0
FROM app_user
WHERE user_name = :'login' AND account_status = 'invited'
  AND delete_ts IS NULL;
SQL
echo "https://$SITE/invite#$TOKEN"
```

Expect `INSERT 0 1` and the link (`INSERT 0 0`: no live invited login by
that name). Send the link privately. Its holder sets a password, enrols
in MFA, and invites everyone else from the user list ("New link" on an
invited login).

UAT is back.

### B1. Webhook

The `shrmpl-hook` agent on UAT serves every app's hook; the other apps'
files show its URL pattern (`grep -h HOOK_URL
/srv/shrmpl/etc/hooks/*.env`). `REF` is one of them: owner, mode and Slack

```bash

[ -e "$DST" ] || install -o "$(stat -c %U "$REF")" -g "$(stat -c %G "$REF")" -m "$(stat -c %a "$REF")" "$SRC" "$DST"
fill "$DST" HOOK_SECRET "$(openssl rand -hex 32)"
fill "$DST" HOOK_SLACK_WEBHOOK "$(getv "$REF" HOOK_SLACK_WEBHOOK)"
```

### B4. fail2ban

One jail per app, `[uat-proto]`, watching this app's nginx access log; its
`ignoreregex` keeps `/api/` lines out of the count (the API answers 4xx to
real users by design and locks out failed logins itself). If


## Lessons

What the first runs taught, carried here as steps above. Add yours.

- A UAT cutover takes an outage: one straight sequence beats staging a
  live swap. Rename the old database aside instead of dropping it or
  moving its ownership in place: the rollback is one rename, not a
  reverse ownership loop or a restore.
- The web publish renames `web-pub/` in the app root as `shrmpl-hook`, so
  the root is `root:shrmpl-hook 1775`; a root-owned root breaks the first
  publish (B024).
- The app's fail2ban jail must ignore `/api/`: the API answers 4xx to real
  users all day, and counting them bans a whole office behind one NAT
  address (B023).
- `uuidgen` is not on every host. Ids come from
  `/proc/sys/kernel/random/uuid`.
- The repo mirrors the host: a monitor or hook file is renamed to its real
  id and committed before anything is exported or cloned, or the export
  says `(dirty)` and the checkout lacks the file.
- A file name the operator types is a file name typed wrong (a `.tar.gz`
  appended twice). Blocks read names from the files themselves (`ls -t`,
  `idof`).
- A `<placeholder>` in a bash paste block is a syntax error: `<` and `>`
  are redirections, so `curl -s http://127.0.0.1:<port>/health` reads
  from a file called `port`. Values are read from files, or set once in
  the shell and checked with `: "${VAR:?}"`, which also keeps a lost
  variable from turning `"$APP_ROOT/etc/"` into `/etc/`.
- No inline `#` comments in local blocks: zsh runs `#` as a command
  without `interactivecomments`, and an apostrophe in one swallows the
  lines after it.
- `sudo -u postgres psql -f /root/...` is refused: `postgres` cannot read
  under `/root`. Root opens the file and pipes it in. Passwords go the
  same way, as `\set` lines on stdin: `psql -v pw=...` puts them on
  argv, visible in `ps`.
- Secrets are generated on the host into the env file and read back from
  it; `fill` writes only over `SERVERONLY`, so a re-run never regenerates
  a secret already in use.
- Monitors for UAT may live on another host, the one that runs nackmon
  and pulsecheck (B074, pending, moves their files under that host's
  mirror). The cert monitor must exist before the first renewal checks in.
- The service account is clearer as `svc-<slug>` (`svc-proto`) in `ps`,
  `ls -l` and the units (B074, pending; this template still says `proto`).
