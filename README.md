# ProtoStack-ReactGo

A production-ready scaffold application combining a Go API server with a React frontend. Designed as a foundation for building secure, multi-tenant CRUD applications with JWT authentication, RBAC, and MFA support.

## Architecture Overview

- **API Server** (`src/api-srv/`): Go application using standard library + pgx, n-tier architecture (handlers, repositories, models)
- **Web App** (`src/web-app/`): React 19 + TypeScript + Vite + Mantine UI, Zustand state management
- **Database**: PostgreSQL with soft deletes, optimistic locking, and multi-tenant security contexts
- **Infrastructure**: in-process key-value store and `log/slog` logging, no external services

Starting a new app from this template? `DERIVING.md` is the checklist; `bin/000-rebrand` does the renaming.

### Key Commands

| Command | Purpose |
|---------|---------|
| `./bin/000-rebrand <slug> "<Name>"` | Rename the app when deriving from this template (see `DERIVING.md`) |
| `./bin/100-build-api-server` | Build the Go API server |
| `./bin/205-migrate-db` | Create or migrate your developer database (`loc_<slug>_db`; first time: `doc/050-dev-env-init.md`) |
| `./bin/510-reset-test-db` | Rebuild a scratch test database (`*_test_db`) |
| `./bin/215-run-api-srv` | Run the API server (supports `--daemon`/`--interactive`) |
| `./bin/220-run-web-app` | Run the web app dev server |
| `./bin/216-stop-local-stack` | Stop the API server and web app dev server |
| `./bin/110-build-web-app` | Build and package web app for deployment |
| `./bin/300-run-tests [all\|go\|unit\|e2e\|py\|load]` | The one test gate (go, vitest, Playwright, pytest, load) |
| `./bin/330-test-load` | Load test a private API it starts on the e2e database (not part of `all`) |

Full command reference: [doc/902-project-commands.md](doc/902-project-commands.md)

## Key Features

- **Authentication**: JWT (HS256) with TOTP-based MFA, session management via the in-process KV store
- **Authorization**: RBAC with grant-based permissions scoped to security contexts
- **Multi-tenancy**: Security context isolation on all tables and queries
- **Security**: CSRF protection, rate limiting, user blocking, Argon2id password hashing, comprehensive security headers
- **CRUD patterns**: Full single and batch operations with optimistic locking and soft deletes
- **Caching**: Conditional fetching with `maxUpdateTs` timestamps for efficient client-server sync
